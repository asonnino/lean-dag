Hydrozoan

  • f Byzantine, c crashed, a slack k ≥ 0: n ≥ 3f + 2c + k + 1.
  • Thresholds: p = ⌊(c + k)/2⌋, q = n − f − c, qFast = n − p, qCert = ⌊(n + f)/2⌋ + 1, qSlow = 2f + c + 1, qWeak = f + p + 1.
  • Fast commit: qFast votes at r + 1. Slow commit: qSlow certificates at r + 2, each referencing qCert votes.
  • Skip: qFast blames at r + 1.
  • Indirect, two rungs: (1) a certificate in the anchor’s history; (2) if no candidate has one, the least candidate with qWeak votes in the anchor’s history.
  • Hydrozoan counts crash faults separately from Byzantine faults and adds a two-round fast path to a Mysticeti-style slow path.
  • The committee has f Byzantine validators, which may behave arbitrarily, c crashed validators, which follow the protocol until they halt and never equivocate, and a slack k ≥ 0, with n ≥ 3f + 2c + k + 1. The table gives each threshold at f = c = k = 1, n = 7.
  • Direct rules: a leader block is fast-committed when qFast round-r + 1 blocks vote for it; it is slow-committed when qSlow validators at round r + 2 each have a certificate, that is, a block referencing qCert votes for it; the slot is skipped when qFast round-r + 1 blocks blame it.
  • The indirect rule has two rungs. The anchor first looks for a certificate in its history; only when no candidate has one does it commit the least candidate with qWeak votes in its history. The second rung serves slots committed by the fast path alone, as the next slide shows.
  • Compared with Mysticeti: a crash fault adds 2 to the committee bound and a Byzantine fault adds 3, and the fast path commits in two rounds when at most p validators are actually faulty.
  • The liveness theorem proved in Lean guarantees the slow commit when a correct quorum, including the leader, is synchronised and fills the rounds of the wave. The two-round fast commit is a separate latency result, which needs every correct validator to take part and at most p actual faults.

Hydrozoan: why the second rung exists

  • No block is a certificate: each round-2 block references only 4 votes, one fewer than qCert = 5.

Optimal-Hydrozoan

  • Hydrozoan’s committee, with at least one tolerated fault (f + c ≥ 1).
  • The fast path tolerates one more fault: pOpt = p + 1, qFastOpt = n − pOpt.
  • FinWhale’s evidence: a round-r+2 block is evidence for L when it references tPlain = n − (2f + c + pOpt) votes for L; or, if it saw the leader equivocate, tEquiv = f + pOpt votes with every rival below tEquiv.
  • Skip: qCert blames and qCert round-r+2 blocks that are evidence for nothing.
  • Indirect: (1) a certificate; (2) qCert evidence blocks in the anchor’s history. No tie-break.
  • Optimal-Hydrozoan lowers the fast quorum by one and replaces Hydrozoan's second rung by a count of evidence blocks, following FinWhale.
  • It keeps Hydrozoan's committee and assumes f + c ≥ 1. The fast path tolerates pOpt = p + 1 faults, with fast quorum qFastOpt = n − pOpt; the table shows that at n = 4, f = 1, Hydrozoan's fast path needs all 4 votes and this one needs 3.
  • A round-r + 2 block is evidence for the leader block L when it references at least tPlain votes for L. If it references votes for two different blocks of the leader, it has witnessed an equivocation, and it must then reference at least tEquiv votes for L and fewer than tEquiv for each rival, so it is evidence for at most one block.
  • Skip: qCert blames at round r + 1 and qCert round-r + 2 blocks that are evidence for no candidate. Indirect: rung 1 is a certificate, rung 2 is qCert evidence blocks in the anchor's history, and no tie-break is needed.
  • Advantages: one fewer vote on the fast path, and a skip proved to occur for every slot with no candidate once a correct quorum fills rounds r + 1 and r + 2. Disadvantages: the skip is decided one round later than Hydrozoan's; validity requires leader exclusion, that a block which has witnessed the leader's equivocation references no block of that leader; and for a slot with a candidate, a counterexample DAG shows that one Byzantine vote can prevent the skip.
  • That this fast path matches Hydrangea's lower bound is the paper's claim, not a theorem here.

Bluestreak

  • n ≥ 3f + 1, quorum n − f.
  • Sparse DAG: only leader blocks must reference n − f blocks. Other blocks reference their own previous block and, optionally, leader blocks.
  • A round-r+2 block claims L by naming it in its payload, or by referencing n − f votes for it.
  • Direct commit: n − f claims for a leader-tagged L.
  • Direct skip: n − f round-r+1 blocks in view, and for each candidate n − f of them that omit it.
  • Indirect: a claim for a tagged L in the anchor’s history.
Compared with Mysticeti: only leader blocks reference n − f blocks; a certificate is replaced by a claim, which only names the block.
Only leader blocks must reference n − f blocks, with the direct commit at r + 2 and n ≥ 3f + 1, as in Mysticeti.
Blocks need not reference a quorum, so chain quality is not shown. Claims require a discipline (slide 37).

Direct skip: n − f round-r + 1 blocks in view and, for each candidate, n − f of them that omit it. Indirect: one rung, a claim for a tagged L in the anchor's history, with no tie-break.

Bluestreak: the claim discipline

  • From round 2, every claim in a correct block’s history must name a certified block exactly two rounds below the claimer.
  • Safety, liveness and every mechanism assume the discipline; garbage collection preserves it.
  • The claim discipline is the assumption on correct validators under which a claim may be relied on as a certificate.
  • Statement: from round 2 on, every claim in the history of a correct block names a block certified exactly two rounds below the claimer, where a block is certified when n − f validators reference it one round above.
  • Diagram: columns are rounds r − 1 to r + 2. Block B at r + 2 claims L at r, and three votes at r + 1 certify L; the shaded window holds everything a validator reads to check B's claim. A claim three rounds below, to L′, is not allowed.
  • Bluestreak's safety and liveness theorems and its mechanisms assume the discipline. Proved in Lean: an execution in which each correct validator builds only on blocks whose claims it has checked satisfies the discipline, and cutting the DAG at a garbage-collection horizon preserves it.
  • Because the check reads no round below r, it can still be made after older rounds are deleted. That the paper's unbounded reading of claims would make garbage collection impossible is an informal argument, not a theorem here.

Mahi-Mahi

  • n ≥ 3f + 1. A wave of w rounds: propose at r, vote at r + w − 2, certify at r + w − 1. At w = 3 this is Mysticeti.
  • A block votes for the least block by the leader at round r in its history (not only among its direct references).
  • Direct skip: n − f blames of the slot; a block blames the slot when its history holds no block of the slot.
  • The leader of a wave is revealed only after the wave, so the adversary cannot direct its message scheduling against it.
Compared with Mysticeti: a longer wave, votes found anywhere in the history, a skip per slot, and an unpredictable leader.
Live with no timing assumption about the network, given a schedule whose leaders include, in every window of slots, a validator whose block commits.
More rounds per commit; it needs an unpredictable leader, drawn by a common coin.
  • Mahi-Mahi lengthens Mysticeti's wave and reveals the leader only after the wave, so that the protocol stays live without timing assumptions.
  • A wave is the sequence of rounds from a slot's proposal to its decision. With wave length w, the leader proposes at r, votes are read at r + w − 2, and certificates, blocks that reference n − f votes, at r + w − 1. The diagram shows w = 5, with two propagation rounds; arrows point from a block into its history. At w = 3 the rule is proved to coincide with Mysticeti's.
  • A block votes for the least block of the leader at round r anywhere in its history. A block blames the slot when its history holds no block of the slot at all, and n − f blames skip the slot.
  • A common coin is a random value that the validators reveal jointly only after the wave; it names the leader, so the adversary cannot know the leader while it schedules messages. The coin is modelled only in the Steelhead part of the development; Mahi-Mahi's liveness theorem assumes instead that the leader schedule names a validator whose block commits in every window of slots, and concludes that some slot in every window commits.
  • Proved in Lean: safety for every w ≥ 2, liveness for w ≥ 4. The advantage is liveness under asynchrony; the disadvantages are more rounds per commit and the need for an unpredictable leader.

Steelhead

  • Each slot has a kind: synchronous (a known leader, short wave ws) or asynchronous (an unpredictable leader, long wave wa).
  • A slot is decided by the rule of its kind, at its own wave; its anchor lies at or above round + w(kind).
  • A period P sets the kinds: round r is asynchronous when r mod P = 0. The period is adapted at intervals of I rounds.
  • Two instances: Mysticeti with Mahi-Mahi (n ≥ 3f + 1, waves 3 and wa ≥ 4), and Odontoceti with Async BlueBottle (n ≥ 5f + 1, waves 2 and 3).
Compared with Mysticeti: two rules on one DAG, chosen per slot, and a controller that chooses how often the asynchronous rule runs.
Short waves while the network is synchronous; liveness under asynchrony.
Two rules, a coin, a period controller, and a failover (slide 44).
  • Steelhead runs two rules on one DAG and chooses per slot which of them decides it.
  • Each slot has a kind: synchronous, with a leader known in advance and a short wave ws, or asynchronous, with a leader drawn by the coin and a long wave wa. The period P sets the kinds: round r is asynchronous exactly when r mod P = 0, and P is changed once per interval of I rounds.
  • Diagram at P = 3, ws = 3, wa = 5: the top row gives rounds 0 to 6 and their kinds. Slot 0 is asynchronous, its wave spans 5 rounds and its anchor lies at round 5 or above; slots 1 and 2 are synchronous, with anchors at or above rounds 4 and 5. Each slot's anchor floor is its round plus the wave of its own kind.

  • Two instances are formalised: Mysticeti with Mahi-Mahi (n ≥ 3f + 1, waves 3 and wa ≥ 4) and Odontoceti with Async BlueBottle (n ≥ 5f + 1, waves 2 and 3). The rule that updates the period is a parameter of the proofs; the paper's update rule is modelled as one instance.

Steelhead: the stall

  • At any period P ≥ ws, an adversary delivers each synchronous leader’s block to exactly f + 1 validators. Neither a commit nor a skip quorum forms.
  • The synchronous slot just below each asynchronous round is then undecided in every view, and the output does not advance beyond it.
  • The asynchronous slot 0 is committed: round 4 certifies block 1. Slot 3 stays undecided whatever slots 0 and 4 decide.
  • At period 1 every slot is proved to be decided.
  • With a fixed period above 1, an adversary can keep Steelhead's output from advancing.
  • n = 4, period 4, ws = 3, v0 Byzantine: rounds 0 and 4 are asynchronous, rounds 1 to 3 synchronous, and the leader blocks are 1, 6, 11 and 12.
  • Step 1: each synchronous leader block is referenced by 2 blocks of the next round and omitted by the other 2, since the adversary delivers it to f + 1 = 2 validators. Both counts are below n − f = 3, so neither a certificate nor a skip quorum forms.
  • Step 2: the theorem, proved in Lean for every period P ≥ ws: if no synchronous candidate is certified and no synchronous slot is skipped directly, no slot at a round congruent to P − 1 mod P is decided in any view. Here that is slot 3, and the output does not advance beyond it.
  • Step 3: the asynchronous slot 0 is committed, since at wave 5 all four round-4 blocks certify block 1; slot 3 stays undecided whatever slots 0 and 4 decide. At period 1 every slot is proved to be decided, under the unpredictability assumption on the coin. For the Mysticeti and Mahi-Mahi pair, ws = 3, so period 2 is covered by neither result.
  • Steelhead therefore needs a way to return to period 1, which is the failover on the next slide.

Steelhead: control and failover

  • The period is changed by a second verdict, read at the asynchronous control slots of each interval.
  • Failover: when the anchor is more than I rounds above the last committed output, the next interval runs at period 1.
  • Under failover a stalled slot is decided almost surely. The probability it is still undecided after M blocks, each of wa·K coins, is at most 2 · ((nwa·K − (n − f − b)wa·K) / nwa·K)⌊M/2⌋, where b is the number of Byzantine validators and K bounds the period.
  • The period of each interval is chosen by the asynchronous rule, and a failover to period 1 makes a stalled slot decided with probability 1.
  • At the asynchronous control slots of each interval, a second verdict, of the asynchronous rule, selects an anchor, and the period of the next interval is computed at that anchor. Failover: when the anchor lies more than I rounds above the round of the last committed output, the next interval runs at period 1; proved in Lean.
