# The presentation

An HTML slide deck on the protocols, properties and mechanisms of lean-dag.
Open `index.html` in a browser.

| Key | Action |
|:---|:---|
| → / Space / Page Down | next step or slide |
| ← / Page Up | previous step or slide |
| N | speaker notes |
| F | full screen |

Printing from the browser gives one page per slide with every step shown.

## Files

| File | Contents |
|:---|:---|
| `outline.md` | the slide outline: text, figures and Lean evidence per slide |
| `parts/*.html` | the slides, one file per range of the outline |
| `index.html` | generated by `tools/build.py` from `parts/`; not edited by hand |
| `theme.css` | every visual choice, as CSS custom properties |
| `deck.js` | navigation, steps, notes |
| `dag.js` | draws DAG figures from witnesses, and charts |
| `witnesses.js` | generated by `tools/ExportWitnesses.lean` from `LeanDagTest` |

Rebuild after editing a part or a witness:

    lake env lean presentation/tools/ExportWitnesses.lean > presentation/witnesses.js
    python3 presentation/tools/build.py

`tools/preview.sh` screenshots slides of one part file with headless Chrome.
`tools/sheet.html?from=1&count=12` shows twelve slides at their final step as
a contact sheet. `tools/layout-audit.html` visits every slide at every step and
lists elements outside the slide, overlapping blocks, figure labels below
11 px and sparse slides; run it with

    "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new \
      --allow-file-access-from-files --virtual-time-budget=30000 \
      --dump-dom "file://$PWD/presentation/tools/layout-audit.html"

Slide numbers in the footer and in links (`#59`, `#59.2` for a step) count the
content slides, as the outline does; part dividers are not numbered.

## Slide markup

```html
<section class="slide" data-part-label="Protocols · Mysticeti">
  <h2>Title</h2>
  <div class="body wide-fig">          <!-- or "body", "body stack" -->
    <div class="text"> … </div>
    <figure class="dag"> <script type="application/json">{ … }</script> </figure>
  </div>
  <aside class="notes"> … </aside>
</section>
```

- Part dividers: `<section class="slide part"><div class="part-number">Part II</div><h1>Protocols</h1></section>`.
- Inline symbols: `<code>n ≥ 3f + 1</code>` (rendered in the body font). Lean
  names and paths in the notes: `<code>…</code>` (rendered monospace).
- Overview slides end with `<div class="compare"><b>Compared with …:</b> …</div>`
  and `<div class="tradeoffs"><div class="plus">…</div><div class="minus">…</div></div>`.
- Mechanism slides end with `<div class="uses"><b>Uses:</b> … <br><b>Gives:</b> …</div>`.
- Any element with `data-step="k"` appears from step `k` of its slide on.
- Diagrams without a DAG use `.flow` / `.box` / `.arrow`, `.columns3`, tables,
  or a chart figure.

## Figures

Three kinds of figure, each specified in JSON; the fields are listed at the
top of `dag.js`.

- `figure.dag` draws the blocks of one witness; `absent` draws a dashed outline for a block the witness lacks. Every block id, round and
  reference comes from `witnesses.js`, so a figure can show only what the
  witness contains. Counts are drawn as brackets beside the counted blocks,
  roles as tags, verdicts as badges connected to their slot.
- `figure.chart` draws a line or bar chart from numbers in the spec, with
  reference lines for thresholds.
- `figure.diagram` draws boxes and labelled arrows on a grid, for mechanisms
  that are not a DAG (flows, layers, state machines).
